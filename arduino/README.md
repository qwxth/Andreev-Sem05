# Счётчик воды на ESP32

ESP32 считает геркон, сохраняет накопленный объём и создаёт свою сеть
**WaterMeter**. Ноутбук подключается к ней, запрашивает показания и сохраняет
новые значения в PostgreSQL. Страница открывается на самом ноутбуке.
Роутер и интернет для работы подготовленного комплекта не нужны.

**Одно подтверждённое замыкание добавляет 10 л.** Замыкание и отпускание
подтверждаются после 100 мс стабильного уровня. D2 горит при замыкании и гаснет
при отпускании. Удержание контакта не добавляет повторных импульсов; начальный
уровень после включения сам по себе не засчитывается.

## Подготовка дома

При наличии интернета открой терминал в папке проекта и выполни:

```bash
./server/prepare.sh
```

Скрипт загружает PostgreSQL и собирает приложение. Повтори его после изменения
серверного кода. Docker должен быть установлен и запущен.

Загрузи в плату `sketches/water_meter_esp32/water_meter_esp32.ino` через Arduino
IDE: плата **ESP32 Dev Module**, фактический USB-порт, кабель с передачей данных.
Оставь **Erase All Flash Before Sketch Upload → Disabled**. Если загрузка
остановилась на `Connecting...`, удерживай BOOT до начала записи.

Настройки уже находятся в `sketches/water_meter_esp32/config.h`. Не заменяй его
образцом ради обновления: в локальном файле сохранена начальная отметка **1090 л**.
`config.example.h` с 0 л предназначен для новой установки.

## Запуск на месте

1. Включи ESP32. Подключи ноутбук к Wi-Fi **WaterMeter**, пароль **12341234**.
   Если система предупреждает «без интернета», оставь это подключение.
   Для адреса ноутбука оставь обычную автоматическую настройку **DHCP**.
2. Из папки проекта запусти:

   ```bash
   ./server/run.sh
   ```

3. Открой **http://localhost:5000** или **http://127.0.0.1:5000**.

Одна команда запускает приложение и PostgreSQL без скачивания и сборки образов.
Терминал оставляй открытым: здесь видны показания и ошибки. **Ctrl+C** останавливает
оба сервиса; история остаётся в базе. Следующий запуск — той же командой.

Страница показывает литры, состояние связи, геркона и историю. Сборщик повторяет
чтение примерно каждые 5 секунд. При потере связи последнее значение остаётся
с отметкой о неактуальности, затем опрос возобновляется автоматически.

ESP32 имеет адрес **192.168.4.1** в сети **192.168.4.0/24**. Адрес ноутбука
фиксировать не нужно: он получает его по DHCP. Допускается один Wi-Fi клиент
одновременно. Это ограничение числа клиентов, а не привязка к конкретному ПК;
фильтра по MAC нет.

Пользователь загружает прошивку и подключает ноутбук к новой сети вручную.
Проверка всей цепочки на физической плате выполняется после этих действий.

## Подключение геркона

Для предоставленной платы с 30 выводами и USB-C:

| Подключение | Контакт ESP32 |
|---|---|
| Один провод двухпроводного геркона | D25, он же GPIO25 |
| Второй провод геркона | GND |
| Питание и загрузка прошивки | USB-C |

При положении платы USB-разъёмом вправо D25 находится в нижнем ряду между D33
и D26. GND — в том же ряду между D13 и VIN, второй контакт справа.
Ориентируйся по подписям: GPIO25 не означает 25-й контакт по порядку.

Старые подключения к Nano, 5 В и резистору на GND должны быть отсоединены.
Для сухого контакта полярности и отдельного питания нет. Включена внутренняя
подтяжка к 3,3 В: разомкнуто — HIGH, замкнуто на GND — LOW.
**5 В на GPIO ESP32 подавать нельзя.**

## Настройки и сохранение счёта

В `config.h` заданы `AP_SSID = WaterMeter`, `AP_PASSWORD = 12341234`, канал 1
и один клиент. `SENSOR_PIN = 25`, `DEBOUNCE_MS = 100`, `LITERS_PER_PULSE = 10.0`.
В локальном файле `INITIAL_TOTAL_LITERS = 1090.0`.

```text
литры = INITIAL_TOTAL_LITERS + сохранённое число замыканий × LITERS_PER_PULSE
```

Сохранены пространство NVS **water-deb10-v4**, ключ **pulses** и формат счётчика.
1090 л — начальная опорная отметка, а не текущий итог. Не меняй её, калибровку,
пространство NVS и разметку памяти при обычном обновлении и не включай erase.
Обычная перепрошивка без стирания с той же разметкой сохраняет NVS; это не
заменяет резервную копию устройства.

Изменения счётчика сохраняются в основном цикле независимо от ноутбука и перед
успешным HTTP-ответом. Неизменившийся счётчик лишний раз не переписывается.
При ошибке памяти или калибровки ESP32 отвечает 503, и сборщик не принимает
показание. Старого интервала сохранения в 10 секунд больше нет. При обрыве
питания до завершения записи последнее событие всё же может потеряться.

Без ноутбука ESP32 продолжает считать **при наличии своего питания**. После
подключения в БД попадает общий итог, без времени отдельных пропущенных
срабатываний. Время строки — момент получения показания компьютером.
Неизменившийся последний итог не добавляет строку, включая перезапуск приложения.
Автоматический сборщик отклоняет показание ниже последнего сохранённого.

## Проверка и диагностика

| Адрес | Назначение |
|---|---|
| `http://192.168.4.1/reading` | Показание непосредственно с ESP32 |
| `http://192.168.4.1/health` | Та же проверка готовности устройства |
| `http://localhost:5000/` | Страница показаний и истории |
| `http://localhost:5000/status` | Состояние опроса, последнее чтение, ошибка |
| `http://localhost:5000/water/stats` | Последние записи из БД |

ESP32 возвращает `liters`, `ready`, `storage_ok`, `contact_closed`, `device_id`
и `uptime_ms`. `/ping` приложения проверяет только Python. Пользовательских USB
Serial-логов в прошивке нет; при сбросе возможен загрузочный текст ROM.

Замкни и отпусти геркон, выдерживая каждый уровень больше 100 мс: D2 должен
загореться и погаснуть, итог — увеличиться на 10 л. **Проверочные замыкания тоже
считаются и сохраняются.** Не стирай рабочую NVS после проверки. При проблемах
смотри терминал приложения и `/status`.

В БД остаются `id`, `liters`, `created_at`. Литры — накопленные снимки:
**их нельзя суммировать по строкам**. `today_liters` старого API — максимум
накопленного показания среди сегодняшних строк, а не расход за сутки.
История хранится в Docker-томе **server_pgdata**: не удаляй его и не выполняй
`docker compose down -v`. Резервная копия до удаления столбца `pulses`:
`server/backups/water_db_before_drop_pulses_20261107_212344.dump`.

## Выполненные проверки

На этом компьютере Docker-образы уже подготовлены. Оба сервиса запущены,
`/ping`, `/status` и `/water/stats` отвечают. Запуск через `run.sh --wait`
проверен с флагами `--no-build --pull never`: скачивание на месте не требуется.

- Прошивка ESP32 полностью собрана с WebServer; тесты обработки геркона прошли.
- 27 тестов Python прошли и на компьютере, и внутри подготовленного образа.
- На отдельной временной БД и имитаторе ESP32 проверены новые показания,
  отсутствие дублей, потеря связи, передача накопленного итога и перезапуск сборщика.
- Интерфейс проверен в браузере в состояниях связи и её отсутствия.
- Рабочая история из **33 строк** при переносе сохранена без изменения значений
  и времени. Проверенная копия перед переносом:
  `server/backups/water_db_before_portable_compose_20261108_161431.dump`.

Имитатор и временная БД удалены. Для проверки настоящей точки доступа осталось
загрузить новую прошивку в плату и вручную подключить ноутбук к WaterMeter.
До этого отметка «Нет связи с ESP32» на странице приложения ожидаема.

## Питание

USB выключенного ноутбука может перестать питать плату. Для накопления без
ноутбука нужен независимый источник. Точка доступа работает постоянно;
срок работы от батарей нужно измерять, это не режим глубокого сна.

Для трёх батареек по 1,5 В используется преобразователь с выходом **5,0 В**:
+5 В подключаются к **VIN**, минус — к **GND**. Перед подключением проверь
напряжение. Надёжная работа от 4,5 В напрямую на VIN для этой платы не подтверждена.
4,5–5 В нельзя подавать на **3V3**. USB и питание через VIN одновременно не
подключай: развязка этой платы не проверена.
